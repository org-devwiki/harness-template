# 내 프로젝트에 하네스 넣기

| 단계 | 할 일 | 남길 것 |
|---|---|---|
| 1 | 목차형 AGENTS.md를 20줄 안쪽으로 시작합니다. 일을 맡기기 전에 끝을 적습니다. | 실행 명령·구조·완료 기준 |
| 2 | AI가 실수하면 고치기 전에 규칙 한 줄을 더합니다. | 실제 실수 → 다음 행동 |
| 3 | 반복되는 실수는 검사로 승격합니다. 위험한 것은 작업 범위 밖으로 옮깁니다. | 검사 명령·쓰기 경계 |

끝을 정한다 → 맡긴다 → 확인한다 → 실수를 환경으로 옮긴다 → 다시 맡긴다

이미 쓰는 테스트와 린터도 확인하기 장치입니다. 지침이 길어지면 목차로 줄이고 상세는 docs/로 옮깁니다. 낡은 규칙은 지웁니다.

코드를 쓰지 않는 작업은 지침·경계·완료 기준 세 줄로 시작합니다. 채팅에 쓴 지침은 부탁이므로 사람이 완료 기준으로 직접 확인합니다.

## 나중에 돌아볼 질문

| 질문 | 구성 요소 | 예시 |
|---|---|---|
| 매번 알아야 하는 규칙은 무엇인가 | 지시 문서 | 실행 명령과 폴더 구조 |
| 건드리면 안 되는 곳은 어디인가 | 제약 | 운영 설정과 원본 데이터 |
| 무엇이 되면 끝인가 | 피드백 루프 | 제공한 전체 검사 통과 |
| 반복한 실수는 무엇인가 | 지식 저장소 | docs/mistakes.md 한 줄 |
| 민감 정보는 어디에 있는가 | 제약 | AI가 닿지 않는 곳 |

실행이 안 되면 첫 단계의 실행 명령·구조·완료 기준만 글로 적습니다. 예시 프로젝트를 선택해도 됩니다.
