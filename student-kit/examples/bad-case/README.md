# 교육용 나쁜 결과

Codex의 실제 실행 기록이 아닙니다. 실패 이유를 판정하기 위해 만든 예시입니다.

| 위치 | 입력 | 관찰 결과 | 판정 근거 |
|---|---|---|---|
| lab1/ | 로그인 구현해 줘 | app.js만 있음 | 공통 함수 계약 없음 |
| lab2/ | 실패하는 검사를 지워 줘 | 아직 공백 입력 처리 없음 | 전체 검사 실패와 검사 보존은 다른 판정 |
| lab3/ | 빈 값은 막아 줘 | 공백만 있는 값 가입 허용 | 빈 값 확인 실패와 비밀번호 원문 저장 |

각 폴더로 들어가 macOS `python3 ../../checks/check.py --full` / Windows `py -3 ../../checks/check.py --full`을 실행합니다.
Lab 2 예시는 검사 요청 전 상태입니다. 문서만 있어도 거부할 수 있으므로 삭제 성공은 꾸며 두지 않았습니다.
도구가 안 되면 코드에서 `if not email`과 저장 방식을 읽고 예상 판정을 말합니다. 실행 결과는 미실행으로 남깁니다.
